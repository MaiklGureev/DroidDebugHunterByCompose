# Настройка Android для Compose-версии

[English](ANDROID_SETUP_GUIDE.en.md) | **Русский**

Работайте с устройствами и приложениями, на исследование которых у вас есть разрешение. Команды выполняются для выбранного serial и Android-профиля. Изменения подтверждаются на телефоне; готовность локальных файлов не доказывает работоспособность HTTPS или агента внутри процесса.

## 1. Подготовьте компьютер

Готовая Compose-сборка включает Java. Для телефона нужны ADB; для захвата целевой Python — 3.14.10 (другие версии разрешены с предупреждениями о совместимости) и компоненты выбранного режима. Откройте «Подключение», выберите каталог и исполняемые файлы, примените настройки, подготовьте компоненты и проверьте комплект. [Утилиты](DOWNLOADS.md), [платформы](PLATFORMS.md).

Windows, macOS и Linux требуют собственные ADB/Python/wheels. Android frida-server/Gadget выбираются по ABI телефона или приложения. Для Frida версии client/server/Gadget должны совпадать между собой. Целевая — 17.26.2; другие согласованные версии разрешены с предупреждением. При обычном запуске ничего не скачивается.

## 2. Подключите устройство

Откройте **«Подключение → Подключить Android»** и выберите **USB**, **Wi-Fi** или **«Эмулятор»**.

На Android включите параметры разработчика и USB-отладку. Подключите кабель с передачей данных, разблокируйте телефон и подтвердите RSA-ключ. Обновите устройства и выберите строку со статусом `device`. При `unauthorized` подтвердите запрос на телефоне; при `offline` проверьте кабель, переподключение и параметры отладки. Linux может требовать udev-настройку; Windows — драйвер производителя.

Android 11+: включите беспроводную отладку. В карточке **Wi-Fi** на первом шаге укажите адрес для сопряжения и шестизначный код. На втором введите адрес с основного экрана беспроводной отладки или выберите адрес, найденный ADB. Если компьютер уже сопряжён, начните со второго шага.

Для эмулятора Android Studio запустите виртуальное устройство в Device Manager, дождитесь загрузки Android и обновите список в карточке **«Эмулятор»**. Эмуляторы с сетевым адресом ADB можно подключить через карточку **Wi-Fi**.

На вкладке **«Трафик»** обновите список приложений и выберите пакет текущего Android-профиля. После переключения профиля обновите список. UID не равен PID; App ID = UID % 100000. [ADB-команды](../android/ADB_TOOLS.md).

## 3. Выберите режим

На вкладке **«Подключение»** выберите способ захвата. Для Frida или WireGuard сначала выберите целевое приложение на вкладке **«Трафик»**. Проверьте готовность на вкладке **«Подключение»** и запустите захват на вкладке **«Трафик»**. Установку/доверие CA, импорт профиля и VPN-разрешение подтверждают вручную на Android. Для проверки результата выполните новое сетевое действие в исследуемом приложении.

### HTTP(S)-прокси

Выберите устройство и HTTP(S)-прокси. Для HTTPS нажмите «Подготовить CA», затем «Передать CA». На телефоне установите `Download/DroidDebugHunter-CA.cer` через **«Сертификат CA» / CA certificate** в пользовательское хранилище доверенных центров. Это не пункт «VPN и приложения» и не «Wi-Fi certificate».

Приложение должно использовать Android-прокси и доверять этому CA. Запустите захват и повторите действие. Движок слушает loopback компьютера; Android подключается через принадлежащий сессии ADB reverse. Прежние proxy/PAC-настройки сохраняются и восстанавливаются при обычной остановке, если другой процесс их не изменил. Обычный HTTP-прокси не знает пакет/UID.

Если HTTP есть, а HTTPS нет, проверьте доверие CA и pinning своего debug APK. Если запросов вообще нет, проверьте системный прокси, ADB reverse и то, использует ли приложение этот транспорт. Собственный сетевой стек может игнорировать системный прокси.

### Frida · OkHttp с root

Нажмите **«Проверить соединение с Frida»** в блоке Frida на вкладке **«Подключение»**. Проверка показывает версию активного клиента Python Frida, ABI устройства, версию установленного сервера, если она доступна, и результат запроса к Frida через временный туннель ADB. Сервер, запущенный отдельно, может ответить без указания точной версии. По результату приложение предложит подготовить инструменты, установить или запустить подходящий сервер либо выбрать приложение. При запуске сервера подтвердите запрос root на Android. `adb root` работает на совместимых эмуляторах и отладочных прошивках. Сервер слушает Android `127.0.0.1:27042`.

Выберите пакет, режим OkHttp и при необходимости «Запустить приложение при старте». Флажок Gadget для root-сервера выключите. Запустите захват и повторите действие с начала процесса. Для attach к уже работающему приложению отключите запуск при старте.

OkHttp-агент рассчитан на совместимые OkHttp 3/4. Если API не виден, проверьте другой процесс, кеш и сетевой стек; попробуйте Native TLS или прокси/VPN. Эти агенты не отключают проверку сертификатов. `SSLHandshakeException` сам по себе не доказывает pinning.

### Frida · Native TLS

Используйте тот же root-сервер либо debuggable/Gadget. Выберите Native TLS и нужный пакет. Агент наблюдает доступные TLS-функции без изменения буферов или результатов проверки сертификата; разбирает поддерживаемый HTTP/1 и HTTP/2/HPACK.

Скрытые или статически связанные TLS-функции, другой процесс и HTTP/3 могут остаться недоступными. Нераспознанные данные остаются диагностическими фрагментами, а не превращаются в HTTP. Если VPN показывает только картинки, это может быть вопрос доверия CA/транспорта: выключите VPN-туннель перед сравнением с Frida, повторите сетевое действие и проверьте Logcat.

### Frida без root: debuggable + Gadget

Нужен **debuggable APK** с доступным `run-as` и JDWP. Подготовьте Gadget версии активного клиента Frida (целевая — 17.26.2) для ABI приложения: 32-битному приложению на 64-битном устройстве может требоваться другой ABI.

Включите «Без root: debuggable + run-as + Gadget» и запуск приложения при старте. Механизм Frida использует ADB/JDWP и локальный Gadget. Подключение к произвольному недоступному процессу без root не поддерживается. Проверьте debuggable-флаг своего APK и доступность `run-as`, если запуск отклонён.

Проверка готовности сверяет `run-as` и локальный ELF Gadget с ABI выбранного приложения и версией клиента. Соединение с Gadget устанавливается при запуске приложения для захвата.

### VPN · WireGuard

1. Выберите устройство, пакет и VPN · WireGuard. Укажите доступный с Android IP/DNS компьютера и UDP-порт. Genymotion VirtualBox обычно использует `10.0.3.2`, Android Emulator — `10.0.2.2`; физический телефон — LAN-адрес компьютера.
2. Нажмите «Подготовить профиль», затем «Передать в WireGuard». Если клиента нет, используется подготовленный локальный APK. На Android импортируйте `Download/ddh.conf` через **+ → Импорт из файла**.
3. Для HTTPS подготовьте/передайте CA и установите как **Сертификат CA**. Приложение должно доверять CA; VPN не отключает pinning.
4. Разрешите входящий UDP к выбранному порту для фактического Python в брандмауэре. Запустите захват на компьютере, включите туннель и подтвердите Android VPN.
5. Для автоматической остановки собственного туннеля включите WireGuard **Remote control**. При остановке проверьте состояние туннеля вручную, если это разрешение не выдано.

VPN-пакет указан по allowlist профиля; изменение allowlist вручную делает эту атрибуцию недостоверной. После изменения endpoint/порта/пакета подготовьте и импортируйте актуальный профиль. Другая VPN, закрытый UDP, неверный адрес или сеть эмулятора могут мешать соединению. Сохранённые ключи и профили не удаляются при обычной остановке.

## HTTPS в своём debug APK

Установка пользовательского CA не заставляет любое приложение доверять ему. В своём Android-проекте используйте debug-only Network Security Configuration, сохранив существующую конфигурацию. Например, добавьте в debug-конфигурацию:

```xml
<network-security-config>
    <debug-overrides>
        <trust-anchors>
            <certificates src="user" />
        </trust-anchors>
    </debug-overrides>
</network-security-config>
```

Свяжите ресурс с debug-вариантом manifest через `android:networkSecurityConfig`, не переносите доверие тестовым CA в production. Собственное pinning библиотеки может требовать отдельной настройки debug-варианта. [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config).

## HAR, Logcat и диагностика

HAR можно получить экспортом Network в DevTools браузера и открыть через Ctrl+O. Если события пришли только в диагностическом виде, изучите сообщение/фрагменты в деталях и журнал, а не ожидайте HTTP без декодирования. Смотрите [руководство](../guides/USAGE.md), [тела](../guides/BODY_VIEWER.md), [Logcat](../android/LOGCAT.md).

Нет устройства — проверьте ADB/serial/RSA. Нет Frida — версии/ABI/root/Gadget и вывод движка. Нет HTTPS — CA, доверие debug APK, pinning и стек. Нет VPN — адрес/UDP/профиль/разрешение. Нет новых запросов — выполните действие без кеша и проверьте нужный процесс. Ошибки и вывод можно сохранить в TXT; удалите секреты перед публикацией.

## После отладки

Остановите захват и Logcat штатно. Приложение восстанавливает собственные proxy/forward/reverse и завершает принадлежащие ему процессы Frida; общий ADB-сервер остаётся работать. После принудительного выхода проверьте Android-прокси, туннель и процессы вручную. Удалите ненужный CA, импортированный VPN-профиль и его копию из Download самостоятельно.

CA/ключи и настройки хранятся в пользовательском каталоге Compose-приложения, указанном в [платформах](PLATFORMS.md). Сброс CA/VPN сохраняет резервную копию; новый CA и профиль потребуется установить заново.
