# Инструменты, версии и настройка

[English](DOWNLOADS.en.md) | **Русский**

Для HAR внешние инструменты не нужны. Java включена в нативные сборки. Для устройств нужен ADB, для захвата нужны Python и компоненты выбранного режима. Для одного инструмента нажмите **«Скачать и подготовить»**, для текущего способа захвата — **«Подготовить недостающие утилиты»**.

## Целевые версии и альтернативы

Базовая конфигурация записана в `tool-setup/tool-versions.json` (проверена 27.11.2026). Это целевые версии, а не гарантия работы на любой прошивке Android или в любом приложении.

| Компонент | Целевая версия | Совместимость / назначение |
| --- | --- | --- |
| Python | 3.14.10, 64-bit | Для целевого прокси нужен Python 3.12+. Другие версии разрешены; работоспособность зависит от метаданных пакетов, API и наличия нативных wheels. |
| ADB / Platform Tools | 37.0.3 | Можно использовать другие версии из SDK/PATH или переносимого архива. Старый ADB может не поддерживать Wi-Fi pairing и другие команды. Сохраняйте библиотеки, `NOTICE.txt` и `source.properties`. |
| Frida client / server / Gadget | 17.26.2 | Другие версии разрешены, но клиент, server и Gadget должны совпадать между собой и соответствовать ABI Android. Для обычного сервера нужен root, для Gadget — подходящее debuggable-приложение. |
| frida-tools | 14.13.1 | Эта версия требует Frida >=17.26.0,<18.0.0. Для другой Frida выберите совместимые frida-tools; зависимости проверит менеджер пакетов. |
| mitmproxy | 12.3.1 | Требует Python >=3.12. У других выпусков могут отличаться требования к Python и API. |
| mitmproxy_rs | 0.12.15 | Для целевого mitmproxy нужен >=0.12.15,<0.13. Wheels должны соответствовать ОС, CPU и Python. |
| WireGuard Android | 1.0.20260315 | Необязательно: только для VPN. Можно использовать совместимое приложение, уже установленное на телефоне. Версия локального APK показывается отдельно от установки на Android. |
| uv (помощник настройки) | 0.13.10 | Необязательный способ подготовки переносимого Python. Можно указать готовый uv. Для Python uv использует сборки Astral python-build-standalone. |

**«Проверить»** показывает обнаруженные версии, пути к файлам и модулям, недостающие компоненты и отличия от целевых. Само отличие версии не блокирует использование. Перед захватом версии нужных компонентов проверяются повторно, предупреждения попадают в журнал. Сервер/Gadget Frida подбирается под фактически загруженный клиент. Несовпадение протокола, отсутствие импортов, несовместимые API или бинарные файлы могут помешать операции.

## Настройка и скачивание инструментов

На вкладке **«Подключение»** у каждого инструмента видны статус, обнаруженная версия, версия для скачивания, папка и параметры. ADB общий для USB, Wi-Fi и эмулятора. Версию можно изменить кнопкой **«Изменить версию для скачивания»**. Если в инструмент входит несколько пакетов, для каждого есть своё поле в общем диалоге. Путь к Python и способ его установки выбираются в блоке Python. Общая папка инструментов и кеш загрузок всегда видны.

- **«Скачать вручную»** открывает ссылки и инструкции по размещению файлов. После размещения файлов или сохранения пути нажмите **«Проверить утилиты»**.
- **«Скачать и подготовить»** скачивает и подготавливает один компонент в выбранной папке. **«Подготовить недостающие утилиты»** пропускает работающие компоненты. Их версии остаются видны вместе с предупреждениями о совместимости. Чтобы скачать другую версию, измените версию для скачивания, затем нажмите **«Скачать и подготовить»**.

Для **ADB** на Windows, macOS и Linux x86‑64 откройте **«Изменить версию для скачивания»** и выберите **«Последняя версия от Google»**. Кнопка **«Скачать и подготовить»** установит актуальный ZIP Google в папку инструментов и покажет обнаруженную версию. Для обновления снова откройте этот диалог. Вариант **«Конкретная версия»** позволяет выбрать номер выпуска. На Linux ARM64 укажите путь к нативному `adb` из вашего дистрибутива или выберите совместимый ZIP и нажмите **«Подготовить локальный ZIP»**. [Загрузки Android Platform Tools](https://developer.android.com/tools/releases/platform-tools) · [Руководство по платформам](PLATFORMS.md)

При ошибке компонента независимые шаги продолжаются. Например, WireGuard подготавливается и при недоступном Python. Шаги без обязательной зависимости помечаются как **«Пропущено»**. Для повтора загрузки ADB используйте его кнопку. Для инструментов захвата нажмите **«Повторить незавершённые шаги»**.

Способ установки, версии, настройки офлайна и кеша и пути сохраняются для каждой ОС и архитектуры.

## Способы установки и ограничения прав

1. **Переносимый Python через uv:** загружает закреплённый архив uv с проверкой SHA-256 и создаёт собственный Python/venv внутри папки инструментов. Системные Python, JDK/JRE, изменение PATH и повышение привилегий не требуются. Этапы установки Python и pip видны в живом журнале.
2. **Существующий Python + локальное venv:** создаёт окружение выбранным интерпретатором. Нужны `venv` и `pip`/`ensurepip`; в некоторых дистрибутивах Linux это отдельные системные пакеты.
3. **Существующий Python + локальные пакеты:** использует pip интерпретатора с `--target`, устанавливая пакеты в папки компонентов, без изменения глобальных пакетов. Подходит, если создание venv недоступно. Для скриптов подготовки нужен Python 3.11+, для целевого прокси — 3.12+.

Во всех способах пакеты устанавливаются в `frida-python/` и `proxy-python/`; приложение добавляет их в `PYTHONPATH`. При другом Python или пользовательских версиях зависимости подбираются по метаданным пакетов, а не принудительно берутся из снимка для Python 3.14. Перед заменой компонента проверяются импорты; при ошибке прежняя установка сохраняется.

Выберите папку пользователя или нажмите **«Папка данных приложения»**. При запрете запуска/загрузок попробуйте разрешённый готовый Python/ADB, локальное venv, другую папку или согласованные офлайн-файлы. Мастер не повышает привилегии, не запускает `sudo`, не устанавливает драйверы и не меняет политики системы. Для USB-драйверов/правил udev может понадобиться администратор; альтернатива — Wi-Fi ADB. В ручной инструкции есть WinGet `--scope user`, Scoop и Homebrew, но эти способы тоже могут быть недоступны или ограничены.

В комплект Frida входят h11/hpack для декодирования Native TLS без пакетов прокси. Движки Frida и прокси используют отдельные каталоги Python-пакетов, чтобы не смешивать версии зависимостей.

## Прогресс, отмена и повтор

Во время настройки видны текущий этап и живой журнал. При загрузке файлов показываются байты и проценты, если сервер сообщает размер; иначе индикатор остаётся неопределённым. Для установки pip/uv отображаются этапы и вывод команд, без выдуманного общего процента. **«Отмена»** останавливает запущенные приложением процессы и удаляет незавершённые прямые загрузки. Готовые файлы кеша можно использовать повторно. После создания не переносите управляемый Python: пути venv могут зависеть от его расположения.

## Офлайн-подготовка

Включите **«Офлайн»** и выберите кеш. Поле **«Локальный ZIP Platform Tools»** позволяет импортировать архив напрямую. Указанный файл имеет приоритет перед кешем и сетью. Выберите его ревизию через **«Конкретная версия»** или **«Последняя версия от Google»**, чтобы использовать номер выпуска из архива. В офлайн-режиме этот вариант берёт подходящий `platform-tools-latest-*.zip` из `downloads/adb/` или выбранного кеша. Можно также указать локальный uv.

Структура кеша:

```text
adb/platform-tools_r37.0.3-win.zip          # darwin/linux для этих ОС
frida/frida-server-17.26.2-android-arm64.xz  # также arm, x86_64, x86
frida/frida-gadget-17.26.2-android-arm64.so.xz
wireguard/com.wireguard.android-1.0.20260315.apk
uv/uv-x86_64-pc-windows-msvc.zip            # архив для вашей ОС/CPU
wheelhouse/capture/                        # wheels Frida и зависимостей
wheelhouse/proxy/                          # wheels прокси и зависимостей
uv/                                       # кеш Python/пакетов uv
```

В именах используйте выбранные версии. Офлайн-режим не выполняет сетевых загрузок. Для переносимого Python нужен заранее заполненный кеш Python и seed-пакетов uv: одного uv недостаточно. Альтернатива — готовый Python с pip. Подготовьте полные wheelhouse под ту же ОС/CPU/Python. Для ручных архивов Frida проверяются ELF/ABI, но контрольные суммы издателя автоматически не сверяются. Автоматическая загрузка Frida требует SHA-256 из GitHub. Для пользовательских версий ADB используются HTTPS и локальный отпечаток; у целевой версии дополнительно закреплена SHA-256.

## Отдельная загрузка и ручная структура папок

В способах захвата с Frida нажмите **«Комплект Frida: клиент + server + Gadget»** для общей подготовки или скачайте компоненты по одному. **«Скачать вручную»** показывает ссылки нужных версий и кнопки **«Скачать файл»**, **«Скопировать ссылку»**, **«Открыть ссылку»**, **«Открыть папку размещения»**. «Скачать файл» сохраняет исходный архив или APK в кеше. Ссылки Python-пакетов ведут на файлы выбранной версии, где можно выбрать wheels и зависимости для своей платформы. «Скопировать все ссылки» также копирует инструкции размещения. В диалоге можно открыть кеш и увидеть последний скачанный файл.

При запуске приложение пытается создать недостающие папки компонентов и кеша. Если каталог недоступен для записи, появятся предупреждения; запуск продолжится без повышения привилегий. **«Проверить / создать папки»** повторяет попытку после выбора другого каталога. **«Структура папок»** показывает ваш путь и выбранные версии. Эту же структуру можно создать вручную:

```text
tools/
├── platform-tools/      adb(.exe), libraries, NOTICE.txt, source.properties
├── frida-server/        frida-server-<version>-android-<ABI> (ELF)
├── frida-gadget/        frida-gadget-<version>-android-<ABI>.so
├── frida-python/        frida/, frida_tools/, dependencies, *.dist-info/
├── proxy-python/        mitmproxy/, mitmproxy_rs/, dependencies, *.dist-info/
├── android-tools/       com.wireguard.android-<version>.apk
├── .venvs/              Python environments
├── python-managed/      uv-managed Python
└── downloads/           original archives and offline wheels
    ├── adb/             Platform Tools ZIP
    ├── frida/           original .xz files
    ├── wireguard/       original APK
    ├── uv/              original uv archive and uv cache
    └── wheelhouse/
        ├── capture/     Frida wheels + dependencies
        └── proxy/       proxy wheels + dependencies

```

Исходные ZIP/.xz храните в `downloads/`, а в рабочих папках Frida — распакованные ELF/.so. APK не распаковывайте. Не копируйте `.whl` внутрь `frida-python/` или `proxy-python/`: устанавливайте через `pip --target <папка>`. Полный wheelhouse целевых версий можно подготовить командой `python -m pip download --only-binary=:all: --dest <кеш>/wheelhouse/capture -r <runtime>/tool-setup/capture-requirements.txt` (для прокси — соответствующий requirements). Для других версий укажите собственные ограничения версий пакетов. Готовьте wheelhouse под ту же ОС/CPU/Python, что и целевой компьютер.

## Подготовка из командной строки

Из корня репозитория, выбранным Python 3.11+:

```sh
python3 prepare-tools.py --action init
python3 prepare-tools.py --action download --component adb
python3 prepare-tools.py --action download --component capture --version-frida 17.26.2 --version-fridaTools 14.13.1
python3 prepare-tools.py --action download --component proxy --offline --cache /path/to/cache
python3 prepare-tools.py --action check
```

Другие параметры: `--root`, `--component all|frida|adb|server|gadget|capture|proxy|wireguard`, `--version-python`, `--version-adb`, `--version-mitmproxy`, `--version-mitmproxyRs`, `--version-wireguard`, `--adb-archive`. CLI использует существующий интерпретатор; сам Python подготавливается через графический мастер. В Windows используйте `python` либо `prepare-tools.ps1` с `-Offline`, `-Cache` и параметрами версий компонентов.

Установка APK, доверие CA, root и согласие VPN на Android выполняются отдельно. Windows-файлы и wheels нельзя переносить как готовый комплект на macOS/Linux. Сохраняйте лицензии и уведомления.
