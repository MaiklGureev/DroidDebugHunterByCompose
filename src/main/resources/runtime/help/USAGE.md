# DroidDebugHunter

Windows-приложение C# / WPF / .NET 10 x64: Android через ADB, управление Frida и просмотр HTTP-трафика. Зависимости берутся из локальных папок; приложение не скачивает их при запуске.

Пошаговая настройка телефона: [ANDROID_SETUP_GUIDE.md](../ANDROID_SETUP_GUIDE.md). В приложении нажмите «Справка» или F1; на экране «Трафик» кнопка «Как настроить» откроет раздел выбранного режима. Справка встроена и работает офлайн. Её можно оставить открытой во время настройки, скопировать раздел или сохранить весь гайд.

## Запуск

```powershell
dotnet run --project .\DroidDebugHunter
```

Для готовой сборки нужны .NET 10 Desktop Runtime x64 и Python x64. Подготовленный комплект `proxy-python` собран для **Python 3.14 x64**. В «Python / офлайн-клиент» можно указать полный путь к интерпретатору. HAR работает без Python и ADB.

Если прежняя копия приложения блокирует Debug/Release, используйте отдельный каталог:

```powershell
dotnet run --project .\DroidDebugHunter -c Preview
```

Не запускайте две сессии захвата для одного устройства одновременно. Обычное закрытие завершает общий ADB-сервер.

## Устройства и приложения

Включите отладку по USB, подтвердите RSA-ключ на Android → «Обновить» → выберите устройство. Для Wi-Fi Android 11+ сначала выполните сопряжение с кодом, затем подключение; их адреса/порты обычно различаются. ADB подготавливается в `platform-tools` скриптом tools/prepare_tools.ps1.

На вкладках «Трафик» и «ADB-инструменты» пакеты загружаются через ADB для текущего пользователя Android и разделены на «Сторонние» и «Системные». Введите часть имени пакета, UID или App ID: результаты фильтруются сразу. Выберите строку мышью либо стрелками и Enter. Esc закрывает список, × очищает поиск и выбор. Ввод поискового текста сбрасывает предыдущий выбор. «↻ Приложения» обновляет обе группы и сохраняет выбор, если пакет по-прежнему установлен.

UID/App ID показываются, если Android вернул UID. App ID = UID % 100000; это не PID.

Если Android разрешает чтение ресурсов, рядом с пакетом показывается локализованное название приложения. Поиск учитывает название, пакет, UID и App ID. Небольшой встроенный помощник получает названия без root и установки APK; при запрете прошивки доступны пакеты. В командах всегда используется пакет. Названия также показаны в деталях и окнах результатов ADB. В трафике они добавляются для известного пакета захвата; обычный прокси без атрибуции остаётся неизвестным. HAR использует явные `_appName` / `_applicationName`.

Тела запросов и ответов поддерживают Auto, Text, JSON, HTML-текст, Image, HEX и Base64. Кнопка «Сохранить…» экспортирует захваченное тело, включая PNG/JPEG; правой кнопкой можно сохранить текст выбранного вида. [Подробнее о просмотре и сохранении](BODY_VIEWER.md).

Детали запроса открываются отдельным окном: двойной щелчок по строке, Enter, «Детали ↗» или контекстное меню. Таблица на основном экране занимает всю ширину. Можно открыть несколько окон для сравнения; каждое остаётся связано со своим запросом и обновляется при получении ответа. В окне доступны вкладки «Запрос», «Ответ» и «cURL», просмотр и сохранение тел, копирование URL и cURL. Esc закрывает окно.

Опрос каждые 5 секунд обновляет только изменившиеся устройства, сохраняет объекты неизменившихся строк и выбор. Фоновый опрос не отключает элементы управления. Ручная операция отменяет текущий опрос и выполняется сразу.

## Logcat

Отдельная вкладка **Logcat** собирает логи Android через ADB: вся система или выбранное приложение по UID, старт/стоп, фильтры tag/уровня/текста/PID/TID/UID, Regex, копирование и экспорт TXT/CSV/JSONL. Она может работать одновременно с трафиком. [Руководство Logcat](LOGCAT.md).

## Режимы захвата

Выберите режим или нажмите **«Чек-лист»**. Откроется единое окно: подключение устройства и выбор приложения → подготовка режима → ручные действия Android → запуск и проверка данных. Разделы можно раскрыть отдельно, готовые шаги учитываются автоматически, у каждого действия есть справка. [Подробная последовательность, хранение и статусы](CAPTURE_SETUP.md).

Список различает «Нужна настройка», «Остались шаги», «Готов к запуску» и «Недоступно». Проверяемый обязательный шаг блокирует старт при ошибке; ручные шаги и первичная подготовка CA/профиля могут оставаться перед запуском сервера. «Готов к запуску» описывает предварительные условия. Агент в процессе, HTTPS и реальные данные проверяются отдельно после старта. Ручные отметки установки CA и импорта профиля показываются отдельно от автоматических фактов.

Проверка перечитывает ADB, текущий Android-профиль/пакет, Python и модули, локальные агенты, состояние/версию Frida. Она не вызывает su, не устанавливает ПО и не меняет Android-настройки. Действия root, установки и запуска доступны из самого чек-листа.

| Режим | Требования | Особенности |
| --- | --- | --- |
| 1. HTTP(S)-прокси | ADB, без root; приложение должно использовать Android-прокси | Временный прокси устройства через ADB reverse. Для HTTPS нужно доверие CA. Пакет/UID обычному прокси неизвестен. |
| Frida · OkHttp | OkHttp 3/4 и root-сервер либо debuggable/Gadget | Заголовки и доступные тела на уровне Java, в том числе HTTPS внутри процесса. |
| 2. Frida · Native TLS | Экспортируемые SSL_read/write или _ex; root-сервер либо debuggable/Gadget | HTTP/1 и HTTP/2 с HPACK без зависимости от OkHttp. Иной протокол показывается как фрагмент TLS. |
| 3. VPN · WireGuard | WireGuard на Android, подтверждение VPN и UDP-связь с Windows; без root | Конфигурация включает только выбранный пакет. HTTPS требует доверия CA. |

Режим по умолчанию — HTTP(S)-прокси. Для него пакет выбирать необязательно: Android-прокси действует на устройство. Фильтр по пакету не сможет выделить приложение в обычном прокси, поскольку такой метаинформации в HTTP нет. В VPN пакет указан **по allowlist конфигурации**, UID остаётся неизвестным. Изменение allowlist вручную нарушает эту атрибуцию.

### HTTP(S)-прокси без root

Устройство → «1. HTTP(S)-прокси» → «Начать». Движок слушает только loopback Windows, Android подключается через принадлежащий сессии `adb reverse`. Программа сохраняет прежние proxy/PAC-настройки и восстанавливает их при остановке, включая отсутствовавшие значения. Если другой владелец изменил настройки или проброс, очистка сохраняет его изменения.

Для HTTPS откройте параметры захвата (шестерёнка) → «CA → Android». В Android выберите **«CA certificate / Сертификат CA»**, затем `Download/DroidDebugHunter-CA.cer`. Это устанавливает CA в **пользовательское хранилище доверенных центров сертификации**. Для нашего CA не подходят пункты «VPN & app user certificate» и «Wi-Fi certificate»; тип CA одинаков для прокси и WireGuard. Системное хранилище этим способом не меняется. Установка пользовательского CA сама по себе не заставляет приложение доверять ему: настройте доверие своего debug APK.

Для **собственного debug APK** есть шаблоны в `DroidDebugHunter/android-debug`, также копируемые в сборку: network_security_config.xml, manifest и инструкция. Они добавляют доверие только к публичному CA и только в debug-вариант. При существующей сетевой конфигурации добавьте debug-overrides в неё. Собственное certificate pinning библиотеки может требовать отдельной настройки вашего debug-варианта.

### Frida с root-сервером

На вкладке «Устройства» ABI определяется автоматически. Программа выбирает распакованный frida-server **17.26.2** нужной архитектуры из `frida-server`: arm, arm64, x86 или x86_64. ELF проверяется; неподходящая архитектура не подставляется. «Установить на устройство» → «Запустить Frida».

Сервер запускается как root на `127.0.0.1:27042` Android. Проверка устройства и установка/запуск могут вызвать запрос su. `adb root` предназначен для эмуляторов и отладочных прошивок. Windows Core Devkit в папке `frida` не является Android-сервером.

Затем выберите OkHttp или Native TLS, пакет → «Начать». По умолчанию приложение запускается через Frida; снимите «Запустить приложение» для подключения к работающему пакету.

Native TLS наблюдает успешные операции TLS без изменения буферов, результатов вызовов или проверки сертификатов. Скрытые/статически связанные функции, Java TLS без доступных native-экспортов и отдельные стеки не гарантируют захват. HTTP/3 этим агентом не декодируется. Попробуйте прокси/VPN для таких приложений. Нестандартный бинарный поток показывается отдельно и не превращается в выдуманный HTTP-запрос.

### С root: если через VPN видны только картинки

Остановите VPN-захват и выключите туннель WireGuard на Android. В чек-листе Frida проверьте root, установите и запустите frida-server 17.26.2. Выберите **Frida · OkHttp**, приложение и запуск приложения при захвате; флажок режима без root должен быть выключен. Повторите сетевое действие с начала процесса. В F-Droid обновите репозитории, чтобы запросить индекс, а не только изображения из каталога.

Если совместимого OkHttp нет, попробуйте **Frida · Native TLS**. Эти режимы наблюдают HTTP(S) внутри выбранного процесса и не требуют CA прокси. Они не отключают проверку TLS. Ошибка `SSLHandshakeException` в Logcat означает сбой TLS; для вывода о pinning нужна дополнительная диагностика.

При ошибке ADB `more than one device/emulator` во время проброса Frida программа повторяет команду через протокол ADB с явным серийным номером выбранного устройства. Удаление такого проброса также проверяет его владельца. Остальные подключённые устройства сохраняют свои соединения.

Root расширяет доступ, но не гарантирует захват скрытых TLS-функций, HTTP/3, другого процесса или данных из кеша. Текущие агенты работают с выбранным процессом; захват трафика сам по себе не заменяет полный аудит приложения.

### Frida без root для debuggable

Режим Frida → «Без root / CA / VPN» → включите «Frida без root» и «Запустить приложение». Программа проверит run-as, определит ABI **приложения** и передаст локальный Gadget 17.26.2 встроенному механизму Frida через ADB/JDWP.

Нужны debuggable APK, доступный run-as и рабочая отладка JDWP. В сборке есть Gadget всех четырёх архитектур. Подключение к произвольному уже работающему процессу без root этим способом не выполняется. Наличие работающего root-сервера может менять внутренний транспорт Frida; выбранный сценарий не доказывает отсутствие root на устройстве.

### VPN без root

1. Выберите **VPN · WireGuard**, устройство и пакет в чек-листе.
2. Задайте доступный с Android IP Windows и UDP-порт. Genymotion VirtualBox обычно использует `10.0.3.2`, Android Emulator — `10.0.2.2`, физический телефон — LAN-адрес Windows.
3. Нажмите **Подготовить**: CA, ключи и конфигурация сохранятся без запуска сервера. **Профиль → WireGuard** передаст файл в Download и откроет клиент; при необходимости установит локальный APK.
4. WireGuard: **+ → Импорт из файла → DDH_….conf**. Отметьте импорт в чек-листе. Неизменный профиль повторно импортировать не нужно.
5. Для HTTPS передайте CA и установите через **CA certificate** в пользовательские доверенные CA. Отметьте установку. Приложению также нужно доверять этому CA; VPN не отключает pinning.
6. Запустите сервер кнопкой **Начать захват**, затем включите туннель на Android и подтвердите VPN. Для автоматического выключения своего туннеля разрешите Remote control в WireGuard. Выполните сетевое действие в приложении.

WireGuard-сервер принимает UDP на интерфейсах Windows. Входящее соединение должно быть разрешено для **фактического python.exe**. На подключённом эмуляторе проверены TCP и UDP Android → 10.0.3.2 → Python 3.14. Повторная проверка без изменения proxy/VPN-настроек:

```powershell
python .\tools\check_android_network.py --serial 127.0.0.1:6555 --host 10.0.3.2
```

Остановка завершает Windows-сервер и отправляет WireGuard команду выключить только свой туннель. Без Remote control проверьте выключение на Android вручную. CA, ключи, импортированный туннель и Download-копия конфига сохраняются. Локальная папка данных: `%LOCALAPPDATA%\DroidDebugHunter\capture`; ключи в журнал не выводятся.

«Свободный порт» подбирает доступный UDP-порт. После изменения адреса или порта обновите профиль и повторите импорт — ключи сохраняются, отметка прежнего импорта перестаёт применяться. Подготовка профиля и передача на Android доступны до старта сервера. Брандмауэр должен разрешать фактический Python и выбранный UDP-порт.

Для HTTPS в VPN-режиме также выбирайте **CA certificate**, а не «VPN & app user certificate»: установите CA в пользовательские доверенные сертификаты и настройте доверие приложения.

## Запросы, фильтры и cURL

Таблица показывает метод, статус, хост, путь, пакет, App ID и время. Выбор строки открывает URL, заголовки и тела. JSON форматируется, бинарные тела показываются как Base64. Поиск по URL/методу/статусу/заголовкам сочетается с фильтрами по пакету и App ID/UID.

«Скопировать cURL» создаёт команду для **PowerShell 7.3+ и curl.exe** с повторяющимися заголовками и точными байтами тела. Временный файл тела удаляется после выполнения команды. Копирование не отправляет запрос. Неполное тело и поток без HTTP нельзя экспортировать как точный HTTP-запрос.

OkHttp читает безопасные доступные тела до 64 КиБ, не читая пользовательские потоки повторно. Прокси и Native TLS передают тела до 1 МиБ; усечённые тела отмечаются неполными. Для прокси установлен предел HTTP-тела 8 МиБ; более крупные передачи могут завершаться ошибкой движка. Native-декодер ограничивает соединения, потоки и буферную память (64 МиБ). Потерянный фрагмент не считается успешным завершением ответа.

«Импорт HAR» работает без устройства, до 64 МиБ / 20 000 записей. Пакет, App ID и UID читаются только из явных _packageName, _appId, _uid, иначе остаются неизвестными. «Очистить» удаляет журнал из памяти.

Пошаговая инструкция: [HAR — сохранение, импорт и cURL](HAR.md). В окне «Справка» / F1 доступен раздел «HAR-файлы».

## Завершение

Обычное закрытие отменяет операции, останавливает Python-клиенты, восстанавливает свой прокси, удаляет свои пробросы, завершает принадлежащие сессии Frida-серверы по маркеру процесса и выполняет `adb kill-server`. Последнее останавливает общий ADB-сервер Windows, используемый также другими программами. Чужой Frida-процесс автоматически не завершается. Принудительное убийство приложения или отключение устройства могут помешать очистке.

## Подготовка офлайн-комплекта

Зависимости не хранятся в Git. Подготовка при наличии интернета:

```powershell
python .\tools\prepare_frida.py
.\tools\prepare_capture.ps1
.\tools\prepare_proxy.ps1
python .\tools\prepare_extra_tools.py
dotnet build .\DroidDebugHunter.slnx
```

Скрипты готовят четыре сервера и четыре Gadget 17.26.2, проверяя SHA-256 по официальному релизу GitHub. Дополнительно скачивается официальный WireGuard APK с download.wireguard.com; его SHA-256 фиксируется в manifest, отдельная проверка подписи разработчика скриптом не выполняется. Архивы .xz не копируются в сборку: используются распакованные файлы.

Python-пакеты устанавливаются локально в frida-python и proxy-python, глобальное окружение не меняется. proxy-python содержит бинарные расширения для **Python 3.14 x64**; для другого интерпретатора подготовьте каталог заново. Для установки без интернета заранее скачайте wheelhouse на машине с тем же Python и архитектурой:

```powershell
python -m pip wheel -r .\tools\capture-requirements.txt -w .\tools\wheelhouse
python -m pip download --only-binary=:all: -r .\tools\proxy-requirements.txt -d .\tools\proxy-wheelhouse
.\tools\prepare_capture.ps1 -Offline
.\tools\prepare_proxy.ps1 -Offline
```

Переносите каталог сборки целиком вместе с platform-tools, frida-server, frida-python, proxy-python, frida-gadget, android-tools, android-debug и agents. Заранее установите Python 3.14 x64 и .NET 10 Desktop Runtime x64. Интернет во время работы не требуется, кроме обращений исследуемого приложения к его серверам.

WireGuard Android: GPL-2.0, [официальный исходный код](https://git.zx2c4.com/wireguard-android/). Лицензии Python-компонентов сохранены в dist-info. Перед распространением комплекта соблюдайте условия включённых инструментов.

## Проверки

```powershell
dotnet run --project .\DroidDebugHunter.Checks -c Preview
python -m unittest discover -s .\tools -p test_prepare_frida.py
node .\tools\test_okhttp_agent.cjs
python .\tools\test_capture_modes.py
```

WPF-проверки используют отдельный процесс-имитатор ADB: выбор устройств/пакетов, архитектуры, очистка, владение ресурсами, отсутствие сброса списков при опросе, ручное прерывание опроса, реальный запуск Python-прокси из UI и рендеры. Сгенерированный cURL выполняется против локального HTTP-сервера; сравниваются точные байты/заголовки. Python-тесты проверяют HTTP/1 и HTTP/2, неполные TLS-потоки, реальный HTTP/HTTPS-прокси с проверкой сертификатов и запуск WireGuard-сервера/конфигурацию.

Полный Android VPN-сеанс требует импорта и системного подтверждения. Тест запуска сервера не заменяет эту проверку. Фактический охват Native TLS и rootless Gadget зависит от целевого APK/Android и требует проверки на вашем приложении.

Документация: [ADB](https://developer.android.com/tools/adb), [Network Security Configuration](https://developer.android.com/privacy-and-security/security-config), [Frida](https://frida.re/docs/android/), [mitmproxy modes](https://docs.mitmproxy.org/stable/concepts/modes/).

## Неразобранные запросы и исходные данные

Ошибки разбора не удаляют факт захвата. В списке остаются записи RAW/TLS/TCP/UDP, а ошибки известного запроса прикрепляются к нему. В деталях откройте **«Диагностика»**: этап ошибки, канал, направление, адрес, доступные исходные байты и стектрейс Python/JS. Ошибки TLS до появления HTTP также отображаются отдельными строками.

Просмотрщик исходных данных поддерживает HEX, Text, JSON и Base64, копирование и сохранение байт. **«Сохранить отчёт JSON»** сохраняет данные, идентификаторы приложения/устройства и ошибку со стектрейсом. Для Native TLS хранится ограниченный снимок последних 64 КиБ в каждом направлении; для неразобранного сообщения прокси/VPN — до 64 КиБ. Отчёт содержит счётчик байт, смещение и признак усечения.

Если источник не предоставил исходные байты или стектрейс, это отмечается явно. Сбой TLS до HTTP не даёт расшифрованного тела запроса. Для ошибки протокола движка сохраняется само исходное событие (этап `event-json` / `event-ingest`). Неразобранная запись не превращается в выдуманный cURL.
