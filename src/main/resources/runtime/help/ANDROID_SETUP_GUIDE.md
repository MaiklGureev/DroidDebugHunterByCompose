# Настройка Android для DroidDebugHunter

Откройте «Справка» в приложении или «Как настроить» на экране «Трафик». Справка работает офлайн; раздел выбирается по текущему режиму захвата.

Начните с HTTP(S)-прокси. Если приложение его игнорирует — попробуйте VPN. Если доступен Frida-сервер или свой debuggable APK — используйте OkHttp либо Native TLS по сетевому стеку приложения.

## Чек-лист захвата

Один порядок подключения и настройки выбранного режима

**Что требуется:** Локальные инструменты. Для живого захвата — подключённый Android.

**Как понять, что работает:** Все условия запуска выполнены; после старта агент, HTTPS и реальные данные проверяются отдельно.

### Порядок работы

1. На экране «Трафик» выберите режим: откроется «Подготовка захвата». Вернуться можно кнопкой «Чек-лист». Окно можно закрыть и открыть без потери введённых параметров.

2. «Подключение и приложение»: подготовьте инструменты, выберите устройство или подключите новое по USB/Wi-Fi, обновите и выберите приложение. Прокси может захватывать всё устройство без выбора пакета.

3. «Подготовка режима»: для root Frida проверьте root, установите сервер подходящей архитектуры и запустите его. Для debuggable включите запуск приложения и режим без root: проверяются run-as/Gadget. Для прокси подготовьте CA; для VPN задайте адрес/UDP-порт и подготовьте CA с профилем.

4. «Действия на Android»: для VPN передайте профиль в WireGuard и импортируйте DDH_….conf из Download. Для HTTPS установите публичный CA через «CA certificate», в пользовательские доверенные CA. Не выбирайте Wi-Fi или «VPN & app user certificate». Отметьте выполненные ручные шаги в чек-листе.

5. «Запуск и проверка данных»: начните захват. Для VPN после готовности Windows-сервера включите импортированный туннель на Android. Выполните сетевое действие. Наличие агента, HTTPS-ответа и фактических данных отмечается только по событиям текущей сессии.

6. Кнопка «Справка» у каждого шага открывает соответствующий офлайн-раздел. Кнопка «Проверить шаги» перечитывает устройство и модули, сохраняя настройки и выполненные ручные шаги.

### Как рассчитываются статусы

- «Нужна настройка» — обязательный проверяемый шаг не выполнен: например, отсутствует модуль, выбранный пакет или подходящий запущенный Frida-сервер. Шаг показывает причину и действие.

- «Остались шаги» — сервер можно запустить, но остаётся ручная подготовка Android, проверка root либо создание локальных данных при первом старте. «Готов к запуску» означает выполнение предварительных условий, а не гарантированную совместимость любого приложения.

- «Проверено» относится к автоматическому факту; «Подтверждено вручную» — к вашей отметке. Установка CA сама по себе не доказывает доверие конкретного приложения. Доверие проверяется отдельным шагом по наблюдавшемуся HTTPS-ответу.

- После смены устройства или параметров факты проверяются заново. История успешного захвата сохраняется как справочная информация; она не выдаётся за рабочее соединение сейчас.

- Инструменты Windows проверяются и без подключённого телефона. При изменении параметров прежние факты сохраняются для справки, но получают нейтральный статус повторной проверки и не разрешают запуск до подтверждения.

- Текущий Android-пользователь проверяется и в обычном прокси без выбранного пакета. Если пользователь сменился, обновите приложения: установка CA в другом профиле не считается выполненным шагом текущего профиля.

- «Отменить» прерывает выполняемую проверку или подготовку, включая запущенное из чек-листа действие ADB/root. Сохранённые CA, ключи и настройки не удаляются. Для повторной проверки нажмите «Проверить шаги».

### Сохранение и явный сброс

- Постоянная папка: %LOCALAPPDATA%\DroidDebugHunter\capture. «Открыть папку данных» показывает её из чек-листа. CA лежит в proxy, ключи и конфигурации VPN — в profiles, параметры устройств — в devices. Не публикуйте эту папку: там есть закрытые ключи.

- Для каждого устройства запоминаются режим, пакет и Android-профиль, запуск приложения, выбор root/Gadget и адрес/порт VPN. При повторном подключении пакет восстанавливается из актуального списка установленного ПО. При смене Android-пользователя старый выбор не применяется.

- CA общий для прокси/VPN и используется повторно. VPN-профиль привязан к устройству, Android-пользователю и пакету. Смена адреса обновляет профиль с теми же ключами; новый профиль нужно импортировать заново. Ручные отметки связаны с отпечатком CA или точной конфигурации.

- Остановка и закрытие приложения завершают соединения, сохраняя CA, ключи и профили. Download-копия VPN-конфига также остаётся для повторного импорта. При первом запуске обновлённой программы прежний CA и ключи из runtime/proxy текущей сборки переносятся без удаления оригиналов.

- «Сбросить CA и VPN-профили…» требует отдельного подтверждения: удаляет локальные CA/ключи/конфигурации всех устройств и их отметки установки, сохраняет параметры подключения и подготавливает новые данные для текущего прокси/VPN. Во время активного захвата или подготовки сброс запрещён. Старые CA и туннели на Android удаляются вручную.

- Повреждённые либо несовместимые ключи не заменяются автоматически. Восстановите данные или воспользуйтесь явным сбросом. После сброса установите новый CA и импортируйте новые VPN-профили.

- Утрата закрытого ключа при сохранённом публичном CA или VPN-профиле отличается от первой настройки и блокирует запуск. Программа показывает причину в чек-листе; восстановите прежние ключи либо явно сбросьте данные. Подготовка не заменяет потерянные ключи автоматически.

- Целостность сохранённого VPN-профиля и файла ключей проверяется по контрольным суммам. После внешнего изменения подготовьте профиль повторно. Старые метаданные обновляются с прежними ключами; повторный импорт не требуется, если сам конфиг не изменился.

- Для уже подтверждённого сброса отмена недоступна: старые данные удаляются до создания новых и автоматически не восстанавливаются. Отмена обычной проверки и подготовки не удаляет сохранённые ключи.

- При переходе с FridaDebugTool настройки и постоянные данные захвата автоматически копируются в %LOCALAPPDATA%\DroidDebugHunter. Оригиналы остаются в старой папке. Отпечатки CA, VPN-ключи, параметры устройств и ручные отметки сохраняются; из-за одного переименования переустанавливать CA не требуется.

- Если прежняя версия ещё использует хранилище, новая версия временно работает с прежней папкой без создания другого CA. Закройте прежнюю версию и перезапустите DroidDebugHunter для завершения переноса. Уже существующая новая папка не перезаписывается старыми данными.

- Новые профили WireGuard называются DDH_….conf. Прежние импортированные профили FDT_….conf сохраняют имя и ключи, чтобы автоматическая остановка обращалась к нужному Android-туннелю. Имя используемой папки и профиля показано в чек-листе.

## Утилиты Windows

Папки, загрузка и ручная подготовка ADB / Frida / Python

**Что требуется:** Создание каталогов и просмотр инструкций работают без интернета и устройства. Автозагрузка требует сети и Python 3.14 x64. Остановите захват и Logcat перед изменением компонентов.

**Как понять, что работает:** Каталоги созданы, основные файлы обнаружены. Дополнительно проверьте готовность режима захвата; найденные файлы ещё не гарантируют совместимость приложения Android.

### Как подготовить комплект

1. Нажмите Проверить / создать папки. Существующие файлы и инструменты сохраняются. Если каталог приложения защищён от записи, распакуйте portable-сборку в доступную пользователю папку.

2. Для автоматической подготовки используйте Подготовить у нужного компонента. Frida/Gadget скачиваются из GitHub Releases 17.26.2, ADB — из официального Platform Tools ZIP, Python-пакеты — по закреплённым requirements. Установка Python и разрешения Android автоматически не выполняются.

3. Если автоматическая загрузка недоступна, нажмите Официальный сайт и Папка. Скачайте нужные архивы, распакуйте их и разместите файлы согласно PLACEMENT.txt. Для frida-server и Gadget сохраняйте все четыре Android ABI; выбор подходящего сервера выполняется автоматически.

4. Python 3.14 x64 можно установить обычным способом и указать python.exe в Настройки → Инструменты. Полная локальная установка python/python.exe имеет приоритет над PATH при автоматическом выборе. Обычный embeddable ZIP без настройки путей модулей не подходит.

5. После подготовки повторите проверку папок и Проверить режимы на экране Трафик. Не запускайте захват до успешной проверки зависимостей.

### Скрипты из исходников

- setup-tools.bat создаёт каталоги и показывает наличие файлов без загрузки. download-tools.bat запускает явную онлайн-подготовку всего комплекта. Запускайте их из корня исходников.

- Отдельный компонент: powershell -File tools/setup_tools.ps1 -Action download -Component server. Доступны adb, python, server, gadget, capture, proxy и wireguard.

- Ручные ссылки без открытия браузера: powershell -File tools/setup_tools.ps1 -Action manual -Component adb -NoOpen.

- Офлайн: добавьте -Offline. Для ADB передайте -ArchivePath с ZIP; для server/gadget — каталог .xz; для wireguard — APK. Wheels положите в downloads/wheelhouse/frida и downloads/wheelhouse/proxy.

- В готовой сборке эти же скрипты находятся в tool-setup. По умолчанию они работают рядом с exe; -ToolsRoot задаёт явную целевую папку. При обычном запуске программы ничего не скачивается.

## Подключить Android

USB и беспроводная отладка

**Что требуется:** Телефон или эмулятор Android с доступной отладкой по USB. Root для подключения ADB не нужен.

**Как понять, что работает:** Устройство видно в списке со статусом «Готово», а на экране «Трафик» загружаются установленные пакеты.

### На телефоне · USB

1. В настройках Android найдите «О телефоне» → «Номер сборки» и нажмите несколько раз, пока не появится режим разработчика. На разных прошивках путь отличается; используйте поиск настроек.

2. Откройте «Для разработчиков» и включите «Отладка по USB». Подключите телефон кабелем с передачей данных и разблокируйте экран.

3. В запросе «Разрешить отладку по USB?» подтвердите RSA-ключ этого компьютера. При необходимости переключите USB в режим передачи файлов.

### В DroidDebugHunter · USB

1. На вкладке «Устройства» нажмите «Обновить» и выберите телефон. Если ADB не найден, укажите platform-tools/adb.exe из комплекта.

2. Перейдите в «Трафик», выберите Frida/VPN и обновите приложения кнопкой «↻». Введите название приложения, часть пакета, UID или App ID и выберите результат мышью или стрелками и Enter. В списке сразу доступны группы «Сторонние» и «Системные». Esc закрывает список, × очищает поиск и выбор. Текст поиска сам по себе не выбирает приложение. Для обычного HTTP(S)-прокси пакет необязателен. В списке режимов видны готовность и причина недоступности. Нажмите «Проверить» после настройки. Недоступный режим можно выбрать для настройки, но кнопка «Начать захват» выключена. Статус «С условиями» означает, что совместимость приложения, CA или VPN ещё требуется проверить при работе.

### На телефоне и Windows · Wi-Fi, Android 11+

1. Подключите телефон и Windows к одной доступной друг другу сети. На телефоне откройте «Для разработчиков» → «Беспроводная отладка» и включите её.

2. Выберите «Сопряжение устройства с помощью кода». В программе раскройте «Сопряжение Android 11+», введите показанные IP:порт и код, нажмите «Сопрячь».

3. Вернитесь на основной экран беспроводной отладки телефона. Введите его адрес подключения в поле «Адрес подключения» программы и нажмите «Подключить». Порт подключения отличается от порта сопряжения и может измениться.

4. Выберите появившееся Wi-Fi-устройство. Для старого подключения IP:5555 режим ADB TCP/IP должен быть уже включён на устройстве; одно только введение адреса его не включает.

### Если не подключается

- «Нужна авторизация»: разблокируйте телефон и подтвердите RSA-запрос. Если запроса нет, переподключите USB; при необходимости отзовите разрешения отладки в настройках телефона и подтвердите заново.

- Пустой список: проверьте кабель, USB-порт и драйвер производителя Android в Windows. Попробуйте «Перезапустить ADB»; это прервёт и другие ADB-сессии компьютера.

- Wi-Fi не отвечает: проверьте оба порта, сеть и изоляцию клиентов на роутере. Если модель не поддерживает беспроводную отладку, используйте USB.

- «Не в сети»: переподключите устройство и обновите список. Снятие блокировки экрана не заменяет подтверждение RSA.

## HTTP(S)-прокси

Первый способ · без root

**Что требуется:** Рабочее ADB-подключение и приложение, которое использует системный HTTP-прокси Android. Для HTTPS приложение должно доверять CA захвата.

**Как понять, что работает:** После действия в приложении появляются строки запросов. Выбор строки открывает заголовки и тела запроса/ответа.

### На телефоне

1. Подключите Android через ADB и подтвердите отладку. Root, frida-server и WireGuard для этого режима не нужны.

2. Откройте нужное приложение. После старта прокси перезапустите его вручную, если оно сохранило старые сетевые соединения.

3. Для HTTPS установите сертификат через пункт Android «CA certificate / Сертификат CA» в пользовательские доверенные CA, затем настройте доверие приложения по разделу «HTTPS и сертификаты». Пункты «Wi-Fi certificate» и «VPN & app user certificate» для нашего CA не подходят. Для собственного debug APK используйте приложенный debug-шаблон.

### В DroidDebugHunter

1. Выберите устройство → «Трафик» → «1. HTTP(S)-прокси» → «Начать захват». Выбор пакета в этом режиме не ограничивает трафик одним приложением.

2. Программа сама задаст временный прокси Android и ADB reverse. В настройках Wi-Fi телефона вводить IP Windows и порт вручную не требуется.

3. Выполните сетевое действие в приложении, например обновите экран. При необходимости сначала откройте из браузера известный вам HTTP-адрес, чтобы отдельно проверить маршрут без TLS.

4. Откройте запрос в списке. «Скопировать cURL» создаёт команду для PowerShell 7.3+; само копирование запрос не отправляет.

### Если запросов нет или HTTPS не работает

- HTTP виден, HTTPS падает: проверьте CA и доверие приложения. VPN или обычная установка пользовательского CA не отменяют certificate pinning.

- В браузере запросы видны, в приложении — нет: оно может игнорировать системный прокси. Попробуйте VPN или Frida.

- Список выглядит пустым: очистите фильтры «Пакет» и «App ID / UID». Обычный прокси не определяет эти значения; непустой фильтр скрывает неизвестные записи.

- Не меняйте системный прокси вручную во время захвата без необходимости. Если вы измените его, программа сохранит ваши изменения при остановке.

### После отладки

- Нажмите «Остановить», пока устройство ещё подключено. Программа восстановит прежние proxy/PAC-настройки и удалит свой ADB reverse. При обычном закрытии выполняется та же очистка.

- После аварийного завершения приложения проверьте proxy/PAC на Android, если интернет перестал работать. Сброс пользовательских CA вручную требуется только если вы больше не используете этот сертификат.

## Frida · OkHttp

Java HTTP · root или Gadget

**Что требуется:** Приложение с совместимым OkHttp 3/4. Для обычного сценария нужен root и frida-server 17.26.2; для debuggable без root см. отдельный раздел Gadget.

**Как понять, что работает:** После сетевого действия видны запросы выбранного пакета и ответы. HTTPS читается в процессе; CA прокси для этого режима не нужен.

### На телефоне · вариант с root

1. Подключите Android через ADB. На устройстве должен быть работающий root; одного переключателя «Отладка по USB» недостаточно.

2. Когда приложение запросит su через ADB, разрешите root-доступ в менеджере root на Android. На отладочном эмуляторе вместо su может работать «adb root».

3. Подготовьте нужный аккаунт и экран приложения. Если выбрано «Запустить приложение (Frida)», процесс будет запущен через Frida; иначе приложение уже должно работать.

### В DroidDebugHunter

1. Во вкладке «Устройства» выберите Android → «Установить на устройство» → «Запустить Frida». Архитектура сервера подбирается автоматически из локальных файлов 17.26.2.

2. На экране «Трафик» выберите «Frida · OkHttp» и пакет из списка. Для root-сервера оставьте флажок «Frida без root» выключенным.

3. Оставьте «Запустить приложение (Frida)» для запуска с агентом или снимите для уже работающего пакета. Нажмите «Начать захват» и выполните сетевое действие на телефоне.

4. Если root нет, перейдите в «Frida без root · Gadget». Этот вариант работает только для debuggable-приложений с доступной отладкой.

### С root · если через VPN видны только картинки

1. Нажмите «Остановить» в DroidDebugHunter и выключите туннель WireGuard на Android. Активный VPN продолжает влиять на TLS даже после выбора другого режима захвата.

2. В «Устройствах» проверьте root и frida-server 17.26.2. Root используется Frida-сервером; обычный режим VPN сам по себе не получает больше доступа от наличия root.

3. Выберите «Frida · OkHttp» и нужное приложение. В параметрах захвата выключите «Без root: debuggable + run-as + Gadget через ADB». Включите «Запустить приложение при захвате», чтобы агент наблюдал старт процесса, затем начните захват.

4. Повторите действие, которое создаёт сетевые запросы. Для F-Droid обновите репозитории: прокрутка уже загруженного каталога может обращаться только за изображениями, а данные каталога уже находиться в локальном индексе.

5. При отсутствии совместимого OkHttp остановите захват и попробуйте «Frida · Native TLS». Этот режим читает доступные TLS-функции внутри выбранного процесса. CA прокси для этих двух режимов не нужен; они не меняют проверку сертификатов приложения.

6. Проверьте Logcat выбранного приложения на SSLHandshakeException и ошибки сертификата. Такая ошибка подтверждает сбой TLS, но сама по себе не доказывает certificate pinning.

7. Root не гарантирует весь трафик: сеть может работать в другом процессе, использовать скрытые/статические TLS-функции, HTTP/3 или нестандартный протокол. Данные из кеша не создают новых сетевых запросов. Один запуск захвата не является полной проверкой безопасности приложения.

### Если захвата нет

- OkHttp не найден: пакет может использовать Cronet, WebView, собственную библиотеку, другой HTTP-стек или переименованные классы. Выберите Native TLS, прокси или VPN.

- Не удалось подключиться к Frida: проверьте выбранное устройство, запущенный сервер и совпадение версии 17.26.2. Windows Core Devkit не заменяет Android-сервер.

- Видна часть трафика: сетевой код может работать в другом процессе или дочернем сервисе; выбранный пакет не гарантирует подключение ко всем его процессам.

- Тело отсутствует или неполное: агент не читает пользовательские/потоковые тела повторно. Безопасные доступные тела ограничены 64 КиБ; неполный запрос нельзя точно экспортировать в cURL.

### После отладки

- «Остановить» отсоединяет клиент захвата. Сервер можно остановить на экране «Устройства»; обычное закрытие программы завершит сервер, если его запустила эта сессия.

## Frida · Native TLS

Когда OkHttp отсутствует

**Что требуется:** Frida-подключение к процессу: root-сервер 17.26.2 или debuggable/Gadget. TLS-библиотека должна предоставлять доступные SSL_read/write или варианты _ex.

**Как понять, что работает:** В журнале появляются сообщения Native TLS о найденных функциях. Поддерживаемые HTTP/1 и HTTP/2 потоки превращаются в запросы; иной TLS-трафик показывается отдельным фрагментом.

### На телефоне

1. Для root-сценария подключите ADB, разрешите su и запустите frida-server из программы, как в разделе OkHttp. Для варианта без root подготовьте debuggable APK по разделу Gadget.

2. Откройте нужное приложение. Для полного начала сетевого сеанса предпочтителен запуск через Frida; при подключении к работающему процессу старые запросы и начало HTTP-сеанса могут не попасть в захват.

3. Обновите экран или вызовите действие, создающее новое сетевое соединение. Установка CA и настройка Android-прокси для этого режима не требуются.

### В DroidDebugHunter

1. Выберите «2. Frida · Native TLS», устройство и пакет. Обычно оставьте «Запустить приложение (Frida)» включённым.

2. Выберите подходящий способ доступа: запущенный root-сервер либо флажок «Frida без root» для debuggable/Gadget.

3. Нажмите «Начать захват». Проверьте журнал команд: сообщения о TLS-функциях показывают установленные наблюдения. Надпись «ожидаю HTTP-данные» сама по себе не подтверждает, что библиотека найдена.

4. Выполните действие на телефоне. Откройте детали запроса двойным щелчком, Enter или кнопкой «Детали ↗». Запись TX/RX с tls:// — фрагмент потока без восстановленного HTTP, а не готовый запрос для cURL.

### Если запросов нет

- Нет сообщений о найденных функциях: TLS может быть статически связан, экспорты скрыты или приложение использует другой стек. В этой реализации захват не гарантирован; попробуйте прокси/VPN.

- Функции найдены, но данных нет: проверьте пакет/процесс и создайте новое соединение. Обычный незашифрованный HTTP не проходит через SSL-функции этого агента.

- Видны только сырые фрагменты: возможно, пропущено начало соединения или используется другой протокол. Перезапустите захват вместе с приложением.

- HTTP/3/QUIC этот агент не восстанавливает. HTTP/2 поддерживается при попадании нужных кадров и HPACK-состояния в захват.

- Тело обрезано или отмечена потеря фрагмента: это неполный захват. Ограничение тела — 1 МиБ; точный cURL для неполного тела не создаётся.

### После отладки

- Нажмите «Остановить», чтобы снять наблюдения и закрыть клиент Frida. Настройки доверия сертификатам приложение этим режимом не меняет.

## Frida без root · Gadget

Для своего debuggable APK

**Что требуется:** Установленный Android APK с android:debuggable=true, доступные run-as и JDWP. Это не способ подключения к произвольному release-приложению без root.

**Как понять, что работает:** Приложение запускается с Frida Gadget. Далее захват работает по выбранному агенту: OkHttp либо Native TLS.

### В проекте мобильного приложения

1. Соберите и установите свой debug-вариант APK. Нужен именно debuggable установленный пакет, а не только исходники или включённая отладка по USB.

2. Убедитесь, что выбираете package/applicationId debug-варианта: у него может быть суффикс .debug и другой пакет, чем у release.

3. Для захвата через Frida не нужно добавлять CA или вручную встраивать Gadget в APK: программа передаёт локальный Gadget механизму Frida через ADB/JDWP. Доступность этого механизма зависит от Android и приложения.

### На телефоне и в DroidDebugHunter

1. Включите отладку по USB, подтвердите RSA и выберите устройство. Остановите другую активную сессию отладчика, если она занимает JDWP этого приложения.

2. Выберите пакет debug-приложения и режим «Frida · OkHttp» или «2. Frida · Native TLS».

3. В «Без root / CA / VPN» включите «Frida без root: debuggable + Gadget через ADB». Оставьте «Запустить приложение (Frida)» включённым.

4. Нажмите «Начать захват». Программа проверит run-as и подберёт локальный Gadget 17.26.2 по ABI приложения, включая 32-битное приложение на 64-битном Android.

5. После запуска создайте сетевой запрос на телефоне. Для OkHttp нужен совместимый OkHttp 3/4, для Native TLS — доступные TLS-функции; Gadget сам по себе не добавляет поддержку HTTP-стека.

### Если не запускается

- «package not debuggable» или run-as недоступен: установите debug APK своего приложения и проверьте его пакет. Переключатель в DroidDebugHunter не делает release APK отлаживаемым.

- Не включён запуск: этот сценарий требует «Запустить приложение (Frida)»; произвольный attach к работающему процессу без root не реализован.

- Ошибка JDWP/ожидание отладчика: закройте другую debug-сессию, проверьте доступность отладки на устройстве, перезапустите приложение и повторите. Поддержка зависит от прошивки.

- Если на Android уже работает root-сервер Frida, внутренний транспорт может использовать его. Выбор флажка описывает сценарий, но не доказывает отсутствие root на устройстве.

### После отладки

- Нажмите «Остановить», чтобы отсоединить агент. Если встроенный механизм Gadget не подходит вашему Android, используйте прокси или VPN с доверием CA в собственном debug APK.

## VPN · WireGuard

Без root · выбранный пакет

**Что требуется:** Рабочее ADB, официальный WireGuard-клиент на Android и доступный с Android UDP-адрес Windows. Для HTTPS нужно доверие CA внутри приложения.

**Как понять, что работает:** В WireGuard включён нужный туннель и после сетевого действия появляются запросы. «VPN-сервер готов» в Windows ещё не означает подключённый туннель Android.

### В DroidDebugHunter · подготовка

1. Выберите устройство, пакет и «3. VPN · WireGuard». Пакет обязателен: создаваемая конфигурация направляет только его трафик.

2. В «Чек-лист → Параметры режима» укажите IP Windows, доступный с Android. Для Genymotion Desktop с VirtualBox используется 10.0.3.2, для Android Emulator — 10.0.2.2; в других сетевых режимах проверьте доступность Windows отдельно. Для физического телефона используйте LAN-IP Windows, например 192.168.1.10, при доступной общей сети. Не указывайте 127.0.0.1: это сам телефон.

3. Укажите UDP-порт, например 51820, или нажмите «Свободный порт». Если указанный порт занят или зарезервирован Windows, при запуске автоматически подбирается доступный: новое значение видно в параметрах и журнале, оно же записывается в конфигурацию Android. Разрешите входящий UDP для фактического python.exe и выбранного порта в брандмауэре Windows на используемом сетевом профиле; если Python уже разрешён целиком, новое правило не нужно.

4. В «Чек-лист → Подготовка режима» нажмите «Подготовить»: CA и VPN-профиль создаются до запуска сервера. Затем «Профиль → WireGuard» передаст DDH_….conf в Download и откроет клиент, при необходимости установив локальный APK. Повторная подготовка использует сохранённые ключи. Импортируйте профиль, отметьте выполнение в чек-листе и запустите захват; после готовности сервера включите туннель на Android.

### На телефоне · включение туннеля

1. Отключите другой активный VPN, если он мешает подключению. В WireGuard нажмите «+» → импорт из файла → Download → скопированный DDH_….conf. Названия пунктов зависят от языка клиента.

2. Включите импортированный туннель и подтвердите системный запрос VPN от Android. Импорт файла без включения туннеля не запускает захват.

3. Не меняйте список IncludedApplications в конфигурации: он задаёт выбранный пакет. Если удалите ограничение, подпись пакета в DroidDebugHunter перестанет отражать источник трафика.

4. Для HTTPS выполните раздел «HTTPS и сертификаты»: в Android выбирайте «CA certificate», а не «VPN & app user certificate» и не «Wi-Fi certificate». Это пользовательский доверенный CA; для своего debug APK настройте доверие CA. После этого откройте выбранное приложение и вызовите сетевое действие.

5. Для автоматического выключения своего туннеля разрешите Remote control / управление из внешних приложений в настройках WireGuard, если этот пункт доступен в установленной версии.

### Если туннель включён, но запросов нет

- Профиль ещё не подготовлен: выберите устройство и приложение, проверьте адрес/порт и нажмите «Подготовить» в чек-листе. Запуск сервера для передачи профиля больше не требуется. Windows 10013 означает запрет привязки к порту, 10048 — порт занят. Используйте «Свободный порт», обновите профиль и импортируйте изменённую конфигурацию на Android. Системные резервы портов удалять не требуется.

- Нет связи/обмена в WireGuard: проверьте Endpoint, UDP-порт, работающий Windows-сервер, брандмауэр и доступ между устройствами. Неверный IP или изоляция Wi-Fi-клиентов не исправляются установкой CA.

- Обмен есть, HTTPS не работает: проверьте доверие CA и pinning приложения. Наличие VPN не отменяет TLS-проверки.

- Убедитесь, что импортировали конфигурацию именно текущего пакета и устройства. Если изменили IP или порт, импортируйте обновлённый конфиг; старый Endpoint на телефоне сам не меняется.

- Подпись пакета берётся из allowlist конфигурации, UID не определяется из IP-пакетов. Фильтр по App ID/UID может скрыть все VPN-записи.

- В таблице показываются HTTP-запросы поддерживаемого движком трафика; произвольный UDP, игры и все сетевые протоколы не превращаются в HTTP-запросы.

- Видны только изображения: проверьте Logcat на ошибки TLS и выполните действие, заново загружающее данные приложения. При наличии root перейдите к инструкции «Frida · OkHttp → С root · если через VPN видны только картинки». Наличие root не меняет требования CA в VPN-режиме.

### После отладки

- Нажмите «Остановить». Программа завершит Windows-сервер, отправит WireGuard команду выключить свой туннель и сохранит копию конфига в Download для повторного использования. Без разрешённого Remote control выключите туннель вручную, чтобы выбранное приложение не осталось без сети.

- Импортированный туннель в WireGuard и установленный CA остаются на телефоне. Их можно удалить вручную после завершения отладки.

## HTTPS и сертификаты

Доверие CA · собственный debug APK

**Что требуется:** Этот раздел относится к HTTP(S)-прокси и VPN. Frida OkHttp/Native TLS не требуют установки CA прокси.

**Как понять, что работает:** Целевое приложение доверяет CA текущей сборки DroidDebugHunter, и HTTPS-запросы проходят без ошибки сертификата.

### На телефоне · установка CA

1. Сначала запустите HTTP(S)-прокси или VPN: так создаётся локальный CA. В параметрах захвата нажмите «CA → Android». Публичный сертификат будет скопирован в Download/DroidDebugHunter-CA.cer.

2. Для HTTP(S)-прокси и VPN WireGuard выберите один и тот же тип: «Сертификат CA / CA certificate» (сертификат центра сертификации). Обычный путь: «Шифрование и учётные данные → Установить сертификат → CA certificate». Выберите Download/DroidDebugHunter-CA.cer и подтвердите установку. Названия пунктов зависят от языка и прошивки.

3. CA устанавливается в пользовательское хранилище доверенных центров сертификации: проверить его можно в «Доверенные сертификаты → Пользовательские / Trusted credentials → User». Не выбирайте «VPN & app user certificate» или «Wi-Fi certificate»: это сертификаты для аутентификации клиента VPN/приложения или Wi-Fi, а не тип нашего HTTPS CA. Даже в VPN-режиме нужен пункт «CA certificate».

4. Системное хранилище CA этим способом не меняется. Для обычной настройки прокси/VPN переносить CA в системное хранилище не требуется. Само приложение должно доверять пользовательскому CA; для своего debug APK настройте debug-overrides по следующему разделу. Установка CA не гарантирует совместимость со всеми приложениями.

5. Если прошивка не поддерживает прямой переход, откроется общий раздел безопасности, затем при необходимости — главные настройки Android. Найдите «сертификат» через поиск настроек. Если ни один переход не сработал, откройте настройки вручную: файл CA уже находится в Download.

6. Начиная с Android 11, пользовательский CA устанавливается через настройки Android. Системное предупреждение об установке CA и подтверждение пользователем сохраняются. Android может запросить PIN/блокировку экрана. После установки проверьте сертификат в пользовательских доверенных сертификатах.

7. Перезапустите тестируемое приложение и повторите запрос. Доверие браузера не доказывает, что тот же CA принимает нужное приложение.

### В своём мобильном проекте · debug-сборка

1. Откройте папку android-debug рядом с DroidDebugHunter.exe: там находятся готовые XML-шаблоны и README.txt. Добавляйте их в debug source set своего Android-проекта.

2. Скопируйте публичный %LOCALAPPDATA%\DroidDebugHunter\capture\proxy\mitmproxy-ca-cert.pem в app/src/debug/res/raw/droid_debug_hunter_ca.pem. Используйте именно *-cert.pem: файл mitmproxy-ca.pem содержит закрытый ключ и в APK не добавляется.

3. Поместите network_security_config.xml из шаблона в app/src/debug/res/xml/. В app/src/debug/AndroidManifest.xml добавьте к application атрибут android:networkSecurityConfig="@xml/network_security_config".

4. Если проект уже содержит networkSecurityConfig, добавьте debug-overrides в существующую конфигурацию. При конфликте manifest решите слияние в своём проекте, сохранив нужные правила.

5. Пересоберите и установите debug APK. debug-overrides применяются только при android:debuggable=true. Отдельное собственное pinning библиотеки может требовать отдельной настройки debug-варианта.

### Почему установки CA бывает недостаточно

- Приложение может не доверять пользовательским CA или использовать собственные правила TLS. Доверие нужно настроить в вашем debug APK; произвольный release APK от этого не меняется.

- CA хранится в %LOCALAPPDATA%\DroidDebugHunter\capture\proxy и не зависит от Debug/Release или обновления приложения. Откройте папку из чек-листа. Новый CA создаётся только при первом использовании или явном сбросе; после сброса обновите сертификат на Android или в debug APK.

- Прокси/VPN не снимают pinning автоматически. Для своего приложения настройте debug-вариант; альтернативно попробуйте Frida, если устройство/приложение допускает этот способ.

- Проблемы маршрута и доверия CA проверяйте отдельно: сначала убедитесь, что трафик достигает движка, затем разбирайте TLS-ошибку в журнале.

### После отладки

- Если сертификат больше не используется, удалите его из пользовательских CA Android. Программа не удаляет установленный CA при закрытии. Debug-шаблоны и публичный CA держите в debug source set своего проекта.

## HAR-файлы

Сохранение, импорт и cURL

**Что требуется:** Готовый HTTP Archive в формате JSON, до 64 МиБ и 20 000 записей. Для просмотра достаточно запущенного DroidDebugHunter: устройство, ADB, Python, Frida и root не требуются.

**Как понять, что работает:** После «Трафик → Импорт HAR…» в таблице появляются запросы. Можно выбрать строку, посмотреть заголовки/тела, применить фильтры и скопировать cURL.

### Что такое HAR

- HAR — файл со снимком HTTP-запросов и ответов: URL, методы, заголовки, статусы, время и доступные тела. Он содержит только то, что сохранил инструмент записи.

- Импорт не подключается к серверу и не повторяет запросы. В текущей версии DroidDebugHunter есть импорт HAR; сохранение собственного живого захвата в HAR пока не реализовано.

### Как сохранить HAR · Chrome / Edge

1. Откройте нужную страницу, затем F12 → Network / «Сеть». Очистите старый журнал и включите запись. Для сценария с переходами включите Preserve log / «Сохранять журнал».

2. Повторите нужное действие на странице и дождитесь ответа. Записывается трафик, который попал в DevTools этой страницы, а не всех приложений телефона.

3. На панели Network нажмите экспорт HAR; для передачи файла предпочтителен вариант sanitized / без чувствительных данных. Сохраните файл с расширением .har. Названия пунктов зависят от версии и языка браузера.

### Как сохранить HAR · Firefox и Android

- В Firefox откройте инструменты разработчика → «Сеть», повторите действие и в меню действий сетевого монитора выберите Save All as HAR / сохранение всех запросов в HAR.

- Для нативного Android-приложения нужен HAR, экспортированный средством, которое действительно записывает его трафик. Файл настольного браузера автоматически не содержит запросы отдельного Android APK.

### Как открыть HAR в DroidDebugHunter

1. Запустите программу и откройте экран «Трафик». Запускать захват и выбирать Android-устройство не нужно. Для отдельного разбора файла остановите текущий живой захват, если он идёт.

2. Если хотите начать с пустой таблицы, нажмите «Очистить»: текущие записи в памяти будут удалены. Исходный HAR-файл эта кнопка не изменяет.

3. Нажмите «Импорт HAR…» и выберите .har или .json с содержимым HAR. Переименование произвольного JSON в .har не преобразует его в архив запросов.

4. Проверьте сообщение «Импортировано … запросов» и счётчик таблицы. Импорт добавляет записи к текущему списку; повторный импорт создаёт ещё один набор записей. Таблица хранит последние 20 000 записей: при превышении этого общего количества старые удаляются из памяти.

5. Сбросьте прежние фильтры и откройте строку двойным щелчком, Enter или кнопкой «Детали ↗». В отдельном окне доступны URL, сведения об источнике, вкладки «Запрос», «Ответ» и «cURL». Можно открыть несколько запросов для сравнения; повторное открытие той же строки поднимает её окно. Esc закрывает окно. Для тела доступны Auto, Text, JSON, HTML-текст, Image, HEX и Base64. «Сохранить тело…» сохраняет захваченные байты (включая PNG); стрелка рядом открывает выбор исходных байтов или текста текущего представления. HTML показывается без выполнения скриптов и загрузки внешних ресурсов.

### Фильтры и повторение через cURL

- Поиск по методу, URL, статусу и заголовкам сочетается с фильтрами пакета и App ID / UID. В обычном браузерном HAR Android-пакет и UID, как правило, не указаны.

- Пакет и идентификаторы импортируются только из явных полей записи _packageName, _appId, _uid; название — из _appName или _applicationName. Поиск учитывает название и пакет. Если их нет, оставьте фильтры пакета и App ID / UID пустыми: значения остаются неизвестными и по URL не вычисляются.

- Выберите запрос → «Скопировать cURL» или соответствующий пункт контекстного меню. Команда предназначена для PowerShell 7.3+ и curl.exe. Копирование не отправляет запрос; выполнение команды отправит его повторно.

- Для точного cURL нужны полный URL, метод и полное тело запроса. Если HAR не сохранил сырое тело, точное повторение может быть недоступно. Cookies и токены могут быть удалены при экспорте или уже устареть: повторный запрос тогда способен вернуть 401/403.

### Если импорт или просмотр не получился

- «Ожидается HAR 1.2…»: нужен JSON с массивом log.entries; в каждой записи должны быть request и response. Повторно экспортируйте HAR, если файл повреждён, обрезан или содержит обычный JSON/HTML вместо архива.

- Файл больше 64 МиБ или содержит больше 20 000 записей: запишите более короткий сценарий либо разделите архив на корректные HAR-файлы в средстве подготовки. Не обрезайте JSON посередине.

- Импорт успешен, но таблица пустая: нажмите «Сбросить» возле фильтров и проверьте, есть ли записи в исходном архиве. Пустой log.entries не содержит запросов для показа.

- Тело ответа пустое/неполное или показано как Base64: исходный инструмент мог не сохранить содержимое либо сохранить двоичные байты. DroidDebugHunter показывает имеющиеся данные и не скачивает отсутствующее тело заново.

- Нет пакета или App ID: это нормальная ситуация для стандартного HAR без расширенных полей Android. Кнопка «Очистить» удаляет только текущий журнал в памяти программы.

### Перед передачей файла

- HAR может содержать cookies, заголовки авторизации, токены в URL, личные данные и тела запросов/ответов. Даже очищенный экспорт проверьте перед отправкой: удаление служебных заголовков не гарантирует удаления данных из URL и тел.

- Используйте тестовую учётную запись и минимальный сценарий. Реальные HAR исключены из Git через .gitignore; не добавляйте их принудительно. При импорте программа не выполняет автоматическое обезличивание.

### Официальные инструкции браузеров

- Chrome DevTools: https://developer.chrome.com/docs/devtools/network/reference/#save-all-network-requests-to-a-har-file

- Microsoft Edge: https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/reference#save-all-network-requests-to-a-har-file

- Firefox: https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/toolbar/index.html

## ADB-инструменты

Приложение, сеть и диагностика

**Что требуется:** Рабочее ADB-подключение. Для действий приложения выберите установленный пакет из списка. Frida и Python для этой вкладки не нужны.

**Как понять, что работает:** Команда выполняется для выбранного устройства и Android-профиля. Результат или ошибка открываются в отдельном окне с кнопкой «Копировать всё».

### Выбор цели

1. Выберите доступное устройство в верхней панели. Действия пакета находятся на экране «Приложения», сетевые команды и диагностика всего устройства — на экране «Инструменты».

2. Нажмите «↻ Приложения», введите название приложения, часть пакета, UID или App ID и выберите результат мышью или стрелками и Enter. Группы «Сторонние» и «Системные» доступны сразу. × очищает поиск и выбор. При редактировании поля предыдущий выбор сбрасывается; первый пакет автоматически не выбирается.

3. Проверьте устройство, профиль Android и пакет перед действием. Если на телефоне сменился активный профиль, обновите список приложений.

4. Результат действия открывается в отдельном окне. «Копировать всё» копирует вывод, «Сохранить…» экспортирует TXT в UTF-8, Esc закрывает окно. Можно оставить несколько результатов для сравнения. Обновление списков приложений и разрешений не открывает новых окон. Команды видны в общем журнале. «Отмена» прерывает ожидание команды; уже выполненные изменения на устройстве могут сохраниться.

### Запуск и процесс

- Группа приложения: запустить, остановить force-stop, перезапустить. Для запуска у пакета должна быть launcher-активность.

- Запуск/перезапуск с отладчиком включает Java/JDWP для debuggable APK. Подключите IDE к процессу; это отдельный способ от запуска Frida на экране «Трафик».

- Для работающего процесса используйте перезапуск с отладчиком. Остановка и перезапуск могут прервать текущий захват этого приложения.

### Данные и удаление

- Очистка данных, очистка с запуском и удаление для профиля требуют подтверждения с именем пакета, профилем и устройством. По умолчанию выбран отказ.

- Очистка удаляет настройки и вход в аккаунт. Перед очисткой с запуском проверяется launcher. Удаление выполняется только для выбранного Android-профиля.

### Runtime-разрешения

1. Выберите пакет и нажмите «Загрузить разрешения».

2. Выберите объявленное приложением опасное runtime-разрешение, затем «Выдать» или «Отозвать». Текущее состояние показывается рядом с названием и перечитывается после команды.

3. Обычные, signature-разрешения и специальные доступы этим способом не выдаются. Android может отказать по политике/SDK; отзыв разрешения способен завершить процесс.

### Диагностика приложения

- Доступны информация о пакете и путях APK, PID/процессы, открытие настроек приложения и снимок последних логов.

- Logcat ограничен PID и UID выбранного пакета: до 200 строк на процесс, до восьми процессов. При неизвестном UID или отсутствии процесса выводится причина; общий поток логов автоматически не включается.

### Сеть и устройство

- Отдельные группы устройства: Wi-Fi, мобильные данные, IP/маршруты/прокси и настройки Wi-Fi; модель/Android/SDK/ABI/экран/батарея и список процессов.

- Выключение Wi-Fi может оборвать сетевой ADB и захват. При таком подключении программа запросит подтверждение. Для восстановления используйте USB или настройки телефона.

- Поддержка команд зависит от прошивки. Автоматическое повышение прав через su не выполняется. Ошибки Android показываются в результате команды.

## Logcat

Логи системы и приложения, tag и экспорт

**Что требуется:** Рабочее ADB-подключение. Для режима приложения нужен известный UID и поддержка UID-фильтрации прошивкой. Python, Frida и root не требуются для обычных доступных ADB логов.

**Как понять, что работает:** Кнопка «Начать запись» включает живой поток, «Остановить» завершает его. Накопленные строки остаются для фильтрации, копирования и экспорта.

### Запуск

1. Выберите доступное устройство, откройте вкладку Logcat. Для всей системы оставьте «Приложение (UID)» выключенным.

2. Для приложения включите «Приложение (UID)», обновите приложения и выберите строку по названию или пакету. Полный UID привязан к текущему Android-профилю; при его изменении захват прекращается.

3. Выберите буферы и размер истории, затем «Начать запись». Начальная история ограничена, после неё идут новые сообщения. Приложение на телефоне запускается самостоятельно. Перезапуск его PID не меняет фильтр UID.

### Фильтры

- Поиск учитывает исходную строку и сообщение без регистра; Regex включает регулярное выражение. Ошибки шаблона показываются под фильтрами.

- Tag и исключения принимают несколько имён через запятую или точку с запятой. «Точный tag» включает полное совпадение; контекстное меню строки умеет оставить или исключить её tag.

- Уровень работает от выбранного и выше; «Ошибки+» выбирает E/F. PID, TID и UID принимают числа через запятую. Все фильтры сочетаются и применяются без перезапуска потока.

- Снимите автопрокрутку для изучения старых строк. Двойной щелчок или Enter открывает полную запись в отдельном окне с сохранением TXT.

### Экспорт и остановка

- Выделите несколько строк и нажмите «Копировать» / Ctrl+C. Экспорт поддерживает TXT, CSV, JSONL. «Экспорт логов» открывает выбор формата и области: видимые строки по фильтрам либо все строки, ещё находящиеся в памяти. Счётчики относятся к зафиксированному снимку.

- «Очистить окно» не очищает буферы Android. Лимит памяти вытесняет старые строки; перегрузка очереди может пропускать новые. Оба счётчика показаны явно, экспорт утраченные строки не восстанавливает.

- Переход на другой экран сохраняет поток. Смена устройства, перезапуск ADB, «Остановить» или закрытие программы останавливают его. Старые строки помечены исходным устройством.

- Режим приложения — это UID, поэтому пакеты с общим UID могут делить сообщения. Системные сообщения об приложении от ActivityManager и изолированные процессы с другим UID ищите в режиме системы. Доступность логов ограничивается Android и прошивкой; общий поток автоматически не включается, если точный фильтр недоступен.

## Интерфейс и настройки

Навигация, фильтры, окна и клавиатура

**Что требуется:** Для HAR, справки и настроек устройство не требуется. Для живых действий выберите доступное Android-устройство.

**Как понять, что работает:** Рабочая таблица занимает основную область, выбранное устройство видно сверху, параметры сохранены для пользователя Windows.

### Рабочие экраны

- Слева: Анализ → Трафик / Logcat; Управление → Приложения / Устройства; Сервис → Инструменты. Настройки и Справка находятся внизу навигации.

- Устройство выбирается сверху для всех экранов. Кнопка + открывает подключение USB / Wi-Fi / сопряжение Android 11+.

- На экране Приложения выберите пакет. Логи приложения и Трафик приложения передают цель без автоматического запуска; активный поток не переназначается.

- Журнал команд сворачивается снизу; размер открытой области можно изменить перетаскиванием верхней границы.

### Таблицы и сохранение

- Трафик: поиск, быстрые 4xx/5xx / JSON / Изображения, дополнительные фильтры приложения и UID. Колонки и наборы условий доступны над таблицей.

- Logcat: поиск, tag, уровень, Regex; Ещё открывает исключение тегов, PID/TID/UID и точный tag. Фильтры не перезапускают поток.

- Детали HTTP и результаты ADB открываются отдельными немодальными окнами. Возле Сохранить тело есть явное меню исходных байтов или текста вида.

- Экспорт Logcat: выберите видимые/все сохранённые строки и TXT/CSV/JSONL, затем файл. Сохраняется снимок.

### Настройки и сочетания клавиш

- Настройки → Инструменты: ADB, Python, каталог/файл Frida. Параметры CA/Gadget/VPN находятся в диалоге выбранного режима Трафика.

- Тема интерфейса переключается сверху или в Настройки → Поведение: Системная / Тёмная / Светлая. Выбор применяется ко всем открытым окнам сразу и сохраняется автоматически. Системная следует оформлению приложений Windows; режим высокой контрастности имеет приоритет. Автообновление 2–60 с, положение окон и остановка общего ADB находятся в том же разделе. Собственные ресурсы завершаются независимо от переключателя ADB.

- Ctrl+K — команды; Ctrl+F — поиск на текущем экране; Ctrl+` — журнал; F1 — контекстная справка; Enter — детали; Esc — закрыть окно.

- Пути и общие параметры сохраняются кнопкой Сохранить настройки. Колонки, именованные фильтры и размеры окон сохраняются отдельно; pairing-коды и тела захвата не сохраняются в UI-настройках.

## Неразобранный трафик и диагностика

RAW / TLS · исходные байты · стектрейс

**Что требуется:** Для просмотра сохранённых записей устройство не требуется. Новые факты появляются только из источников, подключённых текущим режимом захвата.

**Как понять, что работает:** Даже при ошибке разбора в списке остаётся запись с доступными адресами, исходными данными и причиной ошибки.

### Где смотреть

1. Выберите «Все запросы» и сбросьте фильтры, которые скрывают неизвестные пакет или UID. Неразобранные данные помечаются RAW/TLS/TCP/UDP; это факты захвата, а не выдуманные HTTP-запросы.

2. Откройте запись двойным щелчком. Для RAW/TLS автоматически открывается вкладка «Диагностика»: этап, причина, направление tx/rx, канал, доступный адрес и стектрейс источника.

3. Исходные данные можно просмотреть как HEX, Text, JSON или Base64. Кнопка сохранения в просмотрщике сохраняет доступные исходные байты. «Сохранить отчёт JSON» сохраняет также идентификаторы приложения и устройства, метаданные, ошибку и стектрейс.

4. Ошибка разбора ответа или тела прикрепляется к известному HTTP-запросу. Если запрос ещё не был распознан, создаётся отдельная диагностическая запись. Последующие Native TLS-фрагменты обновляют тот же канал/направление, сохраняя первоначальную ошибку.

### Какие данные доступны

- Native TLS сохраняет последние 64 КиБ наблюдавшихся байт в каждом направлении соединения. Отчёт указывает общий счётчик байт, смещение фрагмента и признак усечения. Прокси/VPN сохраняет до 64 КиБ для неразобранного TCP/UDP-сообщения или доступных данных ошибки.

- При ошибке JSON-протокола движка сохраняются первые 64 КиБ исходного события с этапом event-json / event-ingest. Это данные протокола инструмента, а не обязательно сырые сетевые пакеты.

- Стектрейс Python/JS сохраняется, когда у источника есть исключение. Обычный сетевой сбой может содержать только текст ошибки: отсутствие стектрейса отмечается явно.

- При сбое TLS до HTTP можно сохранить факт соединения, адрес и причину, но расшифрованные байты запроса ещё могут отсутствовать. Наличие root не создаёт данные, которые агент не наблюдал.

- Для RAW/TLS достоверный cURL построить нельзя. Используйте экспорт байт и диагностического отчёта; cURL доступен для полноценно разобранного HTTP-запроса.
