## UI & Design System (Compose Desktop / Multiplatform)
- Always use the `$material-3` skill when creating or refactoring UI screens.
- Use `androidx.compose.material3` components only (avoid legacy `androidx.compose.material` or Swing/AWT UI components unless strictly required for OS integration).
- Never hardcode colors (`Color(0xFF...)`), text sizes, or corner radii — strictly use `MaterialTheme.colorScheme`, `MaterialTheme.typography`, and `MaterialTheme.shapes`.
- Support Light and Dark themes automatically synced with the OS theme (`isSystemInDarkTheme()`).

## Desktop UX, Input & Window Management
- **Pointer & Hover:** Always provide hover states (`Modifier.hoverable` or built-in M3 interactions) and appropriate cursor icons (`Modifier.pointerHoverIcon(PointerIcon.Hand)` for custom clickable elements, `PointerIcon.Text` for selectable text).
- **Keyboard & Focus:** Ensure logical `Tab` focus traversal (`FocusRequester`, `focusProperties`), support `Esc` to dismiss dialogs/popups, `Enter` to submit forms, and standard desktop shortcuts (`KeyShortcut` for `Ctrl/Cmd + S`, `Ctrl/Cmd + F`, etc.).
- **Adaptive Layouts:** Use `WindowSizeClass` or `BoxWithConstraints` to adapt to window resizing. Prefer `NavigationRail` or `PermanentNavigationDrawer` on wide windows instead of bottom bars. Enforce sensible minimum window dimensions (`WindowState`).
- **Desktop Affordances:** Wrap scrollable containers with `VerticalScrollbar` / `HorizontalScrollbar` (`rememberScrollbarAdapter`). Provide `TooltipBox` for all icon-only buttons and ensure every icon has a `contentDescription`.
- **Window Integration:** Utilize native desktop capabilities where appropriate (`MenuBar`, `Tray`, `DialogWindow`, file pickers via platform interop) instead of mobile-style full-screen overlays.

## Architecture, State & Performance
- **Package boundaries.** Match Kotlin packages to their directories. Put feature state, workflows, and models in `hunter.features.<feature>` and its Compose screens in `hunter.features.<feature>.ui`. Use `hunter.core` for platform, resource, process, and localization primitives, and `hunter.ui` for shared Compose components.
- **App composition.** Use `AppState` to construct feature ViewModels, wire cross-feature callbacks, coordinate startup and shutdown, and own shell state such as navigation, confirmations, and the journal. Keep feature workflows in their ViewModels and service code. Pass settings, session factories, and callbacks through constructors so this code remains independent of the application shell.
- **Unidirectional data flow.** Keep `MutableStateFlow` private to its ViewModel and expose read-only `uiState: StateFlow<…>`. Publish immutable snapshots for collections and use narrow flows for consumers that need one field. Collect state in screen composables, pass values down, and send events through explicit ViewModel methods. Use `remember` for local interaction state such as an open dialog, search text, or an unapplied draft.
- **Coroutine ownership.** Use the application scope for session jobs and event consumers that must survive tab switches. Use the shell's `task` callback for finite user operations that share the busy, cancel, and error state. The shell runs one such operation at a time. Inside that operation, call suspending helpers directly. Route blocking file, process, and network work to `Dispatchers.IO` and expensive parsing or filtering to `Dispatchers.Default`. Propagate cancellation and use `NonCancellable` for required cleanup and final persistence.
- **Session lifecycle.** Keep capture and Logcat ownership in their ViewModels and implement process cleanup in the `StreamSession` implementations. Serialize start and stop, verify ownership in process-exit callbacks, and bound queues and retained data. Stop dependent streams when the selected Android transport changes or loses authorization. Before publishing async diagnostics, verify that the device, app, capture mode, and configuration still match their original snapshot.
- **Settings and tools.** Apply settings through `SettingsViewModel` and preserve its serialized save and shutdown flush. Apply tool draft changes through `ToolSetupViewModel`, preserving settings owned by other screens. Preserve successful tool preparation results and retry failed or skipped steps.
- **Tests.** Exercise ViewModel transitions with injected dependencies and `runTest` when changing workflows. Cover relevant cancellation, stale results, session lifetime across tab changes, and persistence using the existing ViewModel tests as examples.
- **Recomposition Optimization:** Use immutable collections (`kotlinx.collections.immutable.ImmutableList`) or `@Immutable` data classes for UI models. Use `derivedStateOf` for rapidly changing states (like scroll offsets or window resize) and provide unique `key` and `contentType` in `LazyColumn` / `LazyRow` / `LazyVerticalGrid`.
- **Previews:** Add `@Preview` (using `org.jetbrains.compose.ui.tooling.preview.Preview`) with both Light and Dark themes for every screen composable.
