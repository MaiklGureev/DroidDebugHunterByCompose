# Выпуск 1.1.0

Workflow `Release` собирает Windows x64, Linux x64 и macOS arm64/x64, проверяет встроенную Java и создаёт установщики/переносимые архивы. Системные JDK/JRE для готовых приложений не требуются. Внешние Android/Python-комплекты в публичные образы не включаются.

Проверка локальной упаковки: `python -m unittest discover -s scripts -p 'test_*.py'`. Версия в Gradle, `packageVersion`, release notes и `RELEASE_TAG` в workflow должны совпадать.

Изменения release workflow/скрипта/инструкций в `master` запускают четыре сборки. Публикация выполняется только при явном префиксе `release:` в сообщении коммита либо при ручном запуске `Release` через `workflow_dispatch`.

После готовности всех четырёх целей отдельный job проверяет commit/version/размер/SHA-256 каждого файла и формирует `SHA256SUMS.txt`. Затем создаёт draft-релиз и тег на точный исходный commit, загружает 15 файлов и делает релиз публичным. Неполные или повреждённые сборки не публикуются. Уже опубликованный релиз автоматически не заменяется.

Сборки разных коммитов могут выполняться параллельно, публикация одной версии выполняется последовательно. Проверка приложения и создание установщика разделены на шаги с лимитом 10 минут каждый; остановившаяся упаковка не блокирует сборку исправленного коммита.

Для публичных бинарных поставок сохраняются notices JRE и зависимостей. Подпись Windows/macOS и Apple notarization настраиваются отдельно; текущие артефакты не подписаны. Лицензия собственного кода остаётся на выбор владельца.
