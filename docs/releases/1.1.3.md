# DroidDebugHunter 1.1.3

**English** | [Русская документация / Release notes in Russian](https://github.com/MaiklGureev/DroidDebugHunterByCompose/blob/v1.1.3/docs/releases/1.1.3.ru.md)

This release adds flexible tool setup, visible installation choices, compatibility checks and download progress. Native packages include Java: **no system JDK/JRE is required**.

## Changes since 1.1.2

- Added visible selection cards for manual, guided and automatic setup, components and Python installation methods. Required choices must be made before preparation; opening Settings starts no downloads.
- Added user-local Python bootstrap through pinned uv, existing-Python venv and local `pip --target` methods. Automatic setup can try alternative methods and a writable user data folder. It does not request elevation, modify the system PATH or install system packages.
- Added detected/target version checks with executable and module paths. Older/newer versions may be used with warnings; Frida server/Gadget selection follows the active client version instead of a fixed release requirement.
- Added individual archive/APK downloads, a complete Frida client/server/Gadget bundle, copyable versioned links, destination/cache folder buttons and file-placement instructions.
- Added download byte/percentage progress when sizes are known, indeterminate progress for other stages, a live installation log and cancellation of owned processes. Cached downloads, explicit local archives and offline wheelhouses are supported.
- Added best-effort directory creation at startup and a manual retry action. Configured missing folders are preserved and created where permitted; inaccessible locations produce warnings. The manual folder layout is documented in English and Russian.
- Validate downloads, ELF/ABI and package imports before activation. Failed package preparation preserves the previous installation. Backup cleanup does not follow directory links.
- Included h11/hpack in the Frida package set for standalone Native TLS decoding. Frida and proxy engines use separate Python package paths so alternative dependency versions are not mixed.
- Extended CI to exercise tool downloads using each packaged application's bundled Java with system Java hidden, creating a private Python and checking ADB without connecting to Android.

The target configuration is Python **3.14.10**, Platform Tools **37.0.3**, Frida **17.26.2**, frida-tools **14.13.1**, mitmproxy **12.3.1**, mitmproxy_rs **0.12.15**, optional WireGuard Android **1.0.20260315** and setup helper uv **0.13.10**. Other versions are allowed; dependency requirements, APIs and wheel availability still apply. Frida client/server/Gadget must match each other. See the [compatibility and setup guide](https://github.com/MaiklGureev/DroidDebugHunterByCompose/blob/v1.1.3/src/main/resources/runtime/help/DOWNLOADS.en.md).

- **Windows:** install MSI, or extract the complete ZIP and run `DroidDebugHunterByCompose.exe`. Keep `app` and `runtime` beside the executable.
- **macOS:** choose the matching CPU architecture, copy the `.app` from DMG to Applications, or extract the complete portable archive.
- **Linux:** install DEB through the package manager, or extract the portable archive and run `./bin/DroidDebugHunterByCompose`. A graphical desktop is required.

Current builds are unsigned; macOS packages are not notarized. System security checks may restrict launching a downloaded application.

HAR analysis works immediately. For devices/live capture, open Settings → Tools and choose a setup approach, components and Python method, or configure existing executables. Downloads require an explicit button press. Public packages do not include an external Python interpreter, ADB, Frida binaries or WireGuard APK. Normal startup downloads nothing. Follow offline Help for CA trust, Frida and Android VPN consent.

## Validation and integrity

Four native CI runners build and test Windows x64, Linux x64, macOS arm64 and macOS x64. Checks cover 73 Kotlin tests, 25 Python tests, bundled Java startup, language persistence, Markdown, isolated development launch and user-local tool setup. Tool setup checks use bundled Java with system JDK/JRE paths hidden, verify private Python/ADB and download progress, and do not connect to Android.

Publication verifies all eight binaries against their source commit, version, size and SHA-256 before creating the release. `SHA256SUMS.txt` covers the release assets; `manifest-*.json` records platform, architecture and exact source commit. All packages are built from the commit tagged `v1.1.3`. The MIT License, third-party notices and first-run instructions in English/Russian are included in the portable archives and as separate downloads.
